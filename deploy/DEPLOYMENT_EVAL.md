# 部署方案评估：GitHub vs VPS

## 项目资源画像（实测）

| 维度 | 实测数据 |
|---|---|
| 单次运行时长 | 约 5-8 分钟（含全文抓取 + 4 次 LLM 调用） |
| 单次运行内存峰值 | < 300MB（本地仅 HTTP + 文本处理，无重量级依赖） |
| 站点体积 | site/ ≈ 380KB，kb/ ≈ 220KB，archive/ ≈ 372KB |
| 存档增长率 | 30 天 × 2 次/天 × ~200KB ≈ 12MB |
| 并发需求 | 无（定时任务，单进程顺序执行） |

## 方案对比

### GitHub Actions + Pages（推荐）

**优势**
- 完全免费，零服务器运维
- 定时 cron 精准（已配 8:00 / 20:00 UTC+8）
- 静态 Pages 托管 + CDN，1G 带宽完全不用考虑
- 存档进 git 仓库天然有版本历史

**注意点**
- 免费 Actions 每月 2000 分钟额度：单次 8 分钟 × 2 次/天 × 30 天 = 480 分钟，**远低于限额**
- 存档（kb/ + archive/）需随仓库 main 分支保留；部署分支用 `force_orphan` 只放最新站点
- 隐私：仓库设为 **private**，Pages 对私有仓库需要 GitHub Pro（否则站点公开）
  - 若纯个人用、可公开，免费档即可
  - 若内容敏感需私有，则转 VPS

### VPS（单核 1G / 20G / 1G 带宽）

**配置评估**
- CPU：单核够用（顺序抓取，无并行压力）✅
- 内存 1G：峰值 <300MB，剩余充裕 ✅
- 硬盘 20G：项目 + 存档（12MB）+ 系统 ≈ 6-7G，**完全够用** ✅
- 带宽 1G：托管静态页富余；抓取出站流量也很小 ✅

**优势**
- 内容完全私有，无公开顾虑
- 可用 crontab 本地时间，不依赖 GitHub
- 可后续扩展 API（如查询接口对外服务）

**劣势**
- 需自行维护（安全更新、进程守护）
- 静态站无 CDN，境外访问稍慢
- 单点故障（服务器宕机则看板不可用）

## 结论与建议

**默认推荐：GitHub Actions + Pages**
- 免费、零运维、定时可靠，本项目资源需求极小
- 唯一限制是私有仓库的 Pages 需 GitHub Pro（$4/月）

**改用 VPS 的场景**：
1. 需要**私有展示**且不想付 GitHub Pro 费用
2. 计划扩展为**可交互查询 API**（知识库对外服务）
3. 希望内容留在自有服务器，不依赖第三方

**你的 VPS 配置完全够用**（单核/1G/20G/1G 带宽），若选择 VPS 部署，仅需注意：
- 设时区 `Asia/Shanghai` 后用本地 cron 0 8,20
- 20G 硬盘预留给系统 + 存档（当前 30 天存档仅 ~12MB，绰绰有余）
